# Collect sessions and assess task candidates

Follow [the current workflow rules](assets/kit/AGENTS.md), revision 2026-10-28. Collect by actual task, preserving original evidence and reading gaps. Product failure, damage, and causal proof are not gates for observing defensive coding. Distinguish the coordinator or reviewer from the tested coding agent; verify native traces before treating secondary reports as the latter's observed behavior.

For a new private workspace, run scripts/init_collection.py with an output path. For an existing workspace, preserve evidence and use this installed skill's current rules rather than relying on an older workspace copy. Inventory and read authorized history with assets/kit/commands/history.py; source metadata and human views are navigation, not complete evidence. Inspect original assignment events and action/result pairs.

Use selected, needs-evidence, and not-selected in the five-column session list; put read/unread ranges in the source ledger. Record observed facts before possible design use. A partial observed stage may qualify while its missing continuation remains explicit. A normal reference names the target behavior it contrasts.

For sessions proposed for long-horizon task design, copy [the candidate card](assets/kit/templates/task-candidate.md) into private storage and link it in design_use_or_reason. Separate the original observation, state dependency, newly constructed elements, carrier reuse/adaptation/new design, and run results. Temporal candidate is a plausible supported dependency, not established causation; Short control does not become long-horizon merely by adding stops.

Use the project's existing failure categories in the card where available. Name the work setting and specific mechanism separately; show which source difficulty the new task retains, especially when a later failure depends on an earlier error. Keep observed family behavior, the proposed specific target, and actual run evidence distinct; a partial clue is not a confirmed hit.

If a candidate becomes a runnable task, apply the card's pre-run checker gate to the actual consumer and a disposable candidate copy. Confirm public roots and response semantics, lawful repeats, and capability timing across the staged correct path; preserve original and versioned checker results separately.

For independent validation, freeze a source manifest without expected labels or explanatory titles and inspect unselected as well as selected sources before comparing. Sources used to revise the rules count as development replays. Keep the report's conclusion limited to the tested pool and workflow version.

Deliver a concise linked report with next unread scope. Only revise rules for an observed problem, check that change, then return to collection. Collection does not authorize paid execution, uploading histories, or publication. Use the detailed reconstruction and submission guides only for authorized follow-up work.
