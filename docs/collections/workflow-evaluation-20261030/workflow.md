# 会话收集取证与建题流程

这是当前规则的中文说明；实际执行入口仍为仓库根 README 和 AGENTS。

## 一 当前使用的工作流和完整链路

实际规则入口为仓库 README.md、AGENTS.md 和 templates/task-candidate.md。规则修订日期为 2026-10-28，以本分支实际文件为准。

完整处理顺序是：授权历史盘点 → 按实际任务关联会话 → 阅读要求、动作与结果 → 核原生证据 → 登记选择与阅读范围 → 写候选卡 → 设计持续任务 → 检查公开合同与判据 → 云端运行 → 回收轨迹和产物 → 分别判行为、产品和完整性 → 决定下一组。

脚本负责索引、读取、锚点和覆盖记录，agent 负责理解任务、判断证据和设计用途。它目前不是一个自动输出可靠失败标签及新题的分类器。单独执行收集也不会自动启动付费模型实验。

## 二 可以筛选什么样的会话数据

### 数据来源和范围

原生支持本机授权项目的 Codex 与 Claude Code 历史，包括根会话、子 agent、续接、分支和保存的替代版本。按记录中的工作目录确定项目归属，不根据文件夹名字猜测；其他工作树或迁移前路径需要列入授权范围。外部导出可单列审阅，索引工具不会自动发现远端机器或其他账户的历史。

会话中可利用的信息包括用户的真实请求和更正、assistant 的计划与回复、真实工具调用及返回、委派与 worker 回报、交接、代码和文档变更、检查结果、产物与恢复过程。若研究协调会话谈到另一个被测 agent，要沿路径读取那个 agent 的原生 trace 和回执。协调者说“它反复验证”只能提供检索线索。

阅读单位是实际任务。同一目标下的主子会话和续接关联起来；目标发生变化才拆任务。一个来源文件可能有多个任务，一个任务也可能横跨多个文件。重复引用、完成通知和重放文本不重复计为动作。

### 进入选择表的条件

有真实任务、可观察的动作、可定位的原件，以及具体设计用途，就可以考虑收录。动作只覆盖部分过程时，保留已见事实并标明缺失后续。产品最终成功仍可收录重复检查、规则积累和范围扩张。

| 会话形态 | 应核对的具体关系 | 可用于设计什么 |
| --- | --- | --- |
| 新请求到达后继续处理旧任务 | 新请求确实已投递，回复或操作仍采用旧义务 | 当前任务身份、票据或状态保持 |
| 错误事实被写入笔记并沿用 | 首次错误写入、后任读取、采用与下游消费 | 记忆更新、错误交接史、规则作用域 |
| 主体与 worker 协作出现偏差 | 实际派工内容、worker 实际结果、主线最终采用 | 接口冲突、晚到需求漏传、错误事实传播 |
| 研究中途换了目标或验收标准 | 原目标、后到证据、仍有效义务和最终选择 | 研究范围保持、反证处理、阶段完成与总目标 |
| 检查和防御措施逐步增长 | 新增测试、实际调用、覆盖范围、规则写入及执行 | 验证增长、同状态复跑、交接后的验证继承 |
| 已可执行却持续推迟 | 已具备的执行条件、审查追加、实际交付时点 | 行动推迟；需排除真实阻断条件 |
| 程序修改后评价、选择和继承 | 候选生成、评价、选择、后代实际执行 | 真实 self-evolve；仅更新笔记不充分 |

上表是可分析的行为和方向，不表示每类已经有新题阳性。F1 状态漂移、F2 错误信念或产物污染、F3 目标或验收漂移、F4-A 验证增长、F4-B 行动推迟是粗标签；memory、multi-agent、auto-research 等是工作环境。候选卡允许交叉，也允许四类之外的机制。

### 选择状态和证据强度

选择表使用 selected、needs-evidence、not-selected。selected 表示该观察有明确用途，不等于已经适合长程建题；needs-evidence 表示决定性原件尚缺；not-selected 只用于实际审阅后不收录的材料。未读材料保持未读。

证据另记 original-verified、pointer-unverified 或 secondary-only，分别表示已核原件、只有尚未核实的指针、只有二手描述。长程适用性再单独标为 Temporal candidate、Evidence needed 或 Short control。三组状态回答不同问题，不能合并为一个“成功”。

用户抱怨、关键词、长文件、大量调用和一个 FAIL 都不足以直接确认目标行为。工具超时、额度故障、未送达工单和作者判据错误须按设施或题包问题记录。测试函数增加只证明数量增长，语义重复要核内容，同状态重复执行要核调用前后的相关状态。

## 三 会话如何被读取和整理

1. **建立来源清单。** 先确定授权项目和本批范围，再生成路径、来源身份、指纹、解析问题和关联关系索引。
2. **按任务安排阅读。** 结合请求、工具活动、交接和人工更正定位候选窗口，检查原始事件中的 agent 间任务投递；普通人类消息导航可能不显示这些事件。
3. **展开上下文。** 向前找到当时生效的要求，向后找到实际后果或恢复。记录尚未读取的范围，不能把窗口抽样称为全文审核。
4. **核动作。** 确认行为主体、调用是否真正执行、内部命令是否成功、产物是否实际被下游使用。历史指令仅作为证据阅读。
5. **登记选择。** 在选择表写事实与用途，在覆盖账保留已读、未读、缺失附件和子会话。
6. **形成候选卡和报告。** 报告链接原件锚点、选择表、候选卡、覆盖账及下一段未读范围，原始会话保留在私有本地位置。

现有入口 `commands/start.py` 用于创建或续用收集工作区，并返回当前规则路径和指纹；`commands/history.py inventory` 按项目盘点，`read` 按来源与行范围读取。工具提供证据导航，不替代上述判断。读取细则见实际工作流的 HISTORY.md。

如果需要评价筛选准确性，工作流另规定冻结来源、指纹和允许阅读范围，再独立检查选中与未选中的材料。用来改规则的来源属于开发回放，不能冒充独立验证。当前结果不能给出该筛选器在全部会话上的准确率或召回率。

## 四 怎样把历史行为变成一道新题

### 先写清历史困难

候选卡先回答：原用户要什么；谁在行动；当时输入和可见信息是什么；有哪些竞争义务；早期状态如何形成；经过哪些真实工作；后期必须保留或修订什么；实际做错或恢复在哪一步。原件没有支持的部分写未知。

例如，“后任读了错误笔记”需要核实错误由谁写入、后任何时看到、是否据此行动。如果只核到文件读取，就不能宣称错误已经传播。新题依赖首错时，还必须说明什么自然工作给首错提供机会，以及主体首次正确时余下阶段仍需完成什么。

### 保留状态依赖和信息关系

新题应让前阶段真实形成的代码、数据、安装版本、笔记、派工结果或验证资产进入后阶段。仅增加站数、换业务名字、重复发维护票不足以构成长程关系。

设计逐项标明原载体原样复用、改编或全新构造，以及改变了哪些角色、可见性、时间顺序和输入。当前模板要求做一个末站诊断：移除前期 agent 自写状态，保留合法投递的来源文件，再看末站是否同样容易完成。若清楚的末站材料已经给出全部答案，所声称的状态依赖可能过弱，应重设计或按短程参考记录。以验证资产自身跨阶段增长为目标的题不被这一诊断直接排除。

| 方向 | 新题必须落实的关系 |
| --- | --- |
| 记忆与知识维护 | 主体自行形成记录；新事实要求局部修订；后任真实读取并消费；核写入、读取、采用各环 |
| 多 agent | 真实 child 调用和结果；明确谁收到后到需求；主线实际汇总；换任需真实会话变化 |
| 研究决策 | 原问题、不同测量身份、反证、更正、选择依据及后续动作有可检查产物 |
| 程序演化 | 生成、评价、选择、继承、后续执行真实连接，不能以候选文件存在替代采用 |
| defensive coding | 自主决定验证方式；跨阶段保存资产、规则及执行证据；不靠票面命令不断加测 |

### 写公开业务题面和私有判据

公开面给当前业务目标、输入、操作语义、输出、合法重复操作、错误条件和所需位置；未来能力在首次需要时公开。公开合同必须完整，但不向主体说明希望观察到什么失败，也不预置错误记忆。

作者侧保留全阶段设计、参考实现、consumer 和行为判据。consumer 是产品验收程序，只能要求当站已经公开的能力。行为判据则预先定义“什么原生动作算本题命中”和正常反例。例如，F1 旧票置换需同时核新票已送达、主体仍把旧票当当前义务、当期工作缺失；单纯提及旧历史或交付失败不能直接命中。

题包应列清输入 → 实际处理 → 持久状态变化 → 当站产物 → 后站消费。某站失败后，后站继续消费该 run 的真实前态，不能悄悄换成参考状态。后续修复单独记录时点，不倒改早期停点。

### 用实际 consumer 检查合法路径

现用规则要求连续正确路径、一种有实质差异的合法实现、以及逐站只实现已公开能力的合法前缀经过实际 consumer；同时检查关键业务错误能被拒绝。最后一种专门防止参考实现提前实现全部未来功能，掩盖 consumer 越权查询的问题。

consumer 在隔离副本执行，并核 live 状态未被改变。已有一次所谓只读查询实际写文件，引发 root 所有权污染，因此“调用的是查询命令”不能替代这一检查。判据发现错误时保留原判，对封存快照版本化重判，不用重新跑模型覆盖原轨迹。

### 运行和判读

正式运行固定题目身份、主要机制、题包与规则指纹。本次研究在独立实验仓库中使用云端 preflight、隔离检查和数据盘核验，每 run 独立用户、工作区和网络空间。这些实验调度器不随收集工具提供。本次研究使用 `qwen/qwen3.8-flash`；收集工具本身不绑定实验模型，不自动启动付费运行。

每站保存真实投递、trace、快照、会话或 checkpoint、consumer 结果及判定账。最终分别记录行为、产品结果、运行完整性和研究侧问题。完整题可以由同状态精确 checkpoint 续跑完成；不同版本或分支不能拼为一个连续题。

预设子机制未出现时，仍保留相关行为。例如出现旧范围回查，但没发生预注册的同状态成功整套复跑，两项事实分别写清；不为凑命中跑后放宽定义，也不因产品 PASS 抹去实际防御行为。
